## 🎓 UNDERSTANDING REAL-TIME LOGS

Log Entry: "✓ Document annual_report ingested (6 chunks)"
Components:
  ✓ = Success indicator (green)
  Document annual_report = Operation target
  ingested = Operation type
  (6 chunks) = Result details
Captured when: Document ingestion completes successfully

Log Entry: "✓ Query from user1 (C1D1) - 4 chunks [verbose]"
Components:
  ✓ = Success indicator
  user1 = User ID
  C1D1 = Company 1, Dept 1
  4 chunks = Relevant documents found
  [verbose] = Response mode selected
Captured when: Query starts (not when answer completes)

Log Entry: "⚠ RBAC: Query blocked for user1"
Components:
  ⚠ = Warning indicator (orange)
  Query blocked = Access denied
  user1 = User attempted access
Captured when: User tries to access restricted data

Log Entry: "✗ Query error: Connection timeout"
Components:
  ✗ = Error indicator (red)
  Query error = Error type
  Connection timeout = Specific error message
Captured when: API request fails

## 🔧 TROUBLESHOOTING QUICK REFERENCE

Problem: Dashboard shows "Unhealthy API" status
Solution: 
  1. Check RAG API running: http://localhost:8001/health
  2. Verify port 8001 is free: netstat -ano | findstr :8001
  3. Restart RAG API server

Problem: No logs appearing after operations
Solution:
  1. Ensure using dashboard (not direct API calls)
  2. Refresh /api/logs endpoint
  3. Check dashboard_server.py terminal for errors
  4. Restart dashboard server

Problem: "Cannot connect to localhost:8000"
Solution:
  1. Check dashboard_server.py is running
  2. Look for port 8000 conflicts
  3. Restart dashboard server

Problem: Dashboard won't load any pages
Solution:
  1. Check browser console (F12) for errors
  2. Verify JavaScript enabled in browser
  3. Clear browser cache and reload
  4. Try different browser

Problem: API calls timeout
Solution:
  1. Check RAG API is processing: watch terminal output
  2. May need to wait for model initialization
  3. Check system resources (RAM, CPU)
